# 0009: One rule set, several boards

*28 November 2026. Accepted. Amends ADR 0006 (its compiled model and save key) for v3 (`docs/design/v3-wales.md` section 1).*

**Context.** v3 plays All Wales first, then regional boards (South East, North, South West, Mid and West). Until now the one board, South East Wales, was written into the shared files: `game.yaml` held its name and councils, `links.yaml` its stubs, `tree.yaml` and `projects.yaml` its valleys branch, `starts.yaml` its starts, and endings, chapters and a bot named the flags `valley` and `city`. A second board would have meant copying files or editing code.

**Decision.**

- **A board is a folder.** `model/board/boards/<id>/` holds what differs by board. Only `board.yaml` is required: the name, the councils in display order, the areas, the map groups, the stubs, and any stops it switches on or off. `branch.yaml` is the board's first branch with its projects. `starts.yaml` and `events.yaml` add to the shared lists. `words.yaml` renames text fields by section and id. The folder name is the board's id.
- **Regional content overrides, never copies.** Shared content stays in `model/board/*.yaml`. A board's entry with a shared entry's id takes its place; a new id is added. A rename in `words.yaml` must name an entry and a text field that exist, or the build fails. The build (`scripts/board/board-content.ts`) folds the folder over the shared files, so the rest of the build sees one set of files.
- **Areas, not flags, in shared conditions.** Endings, starts, chapters and the bot marks said `flag: valley` and `flag: city`, which only the South East means. They now say `area: edge` and `area: core`. Each board defines its areas from the councils' flags in `model/authorities.yaml` (the South East: core the cities, edge the valleys; All Wales will add rural councils to edge). Every board must define `core` and `edge`. Each map group is an area too. The key is `area`, not the design's `group`, because `group` already means a group of people (`groups.yaml`, a law's `backing: { group: young }`). Flags stay where they mean a real feature (coal tips, coast, a port).
- **Places by council.** Places stay in one shared folder, `model/board/places/`. A board takes every place whose council it holds, so All Wales and a region share the Rhondda without a copy. A project or event on a board offers only the places on it.
- **Tree order.** The board's branch comes first. Projects are kept in tree order: each branch's projects together, legacy projects last, so a board's projects can live in its own file without moving anything else.
- **One compiled model per board.** The build writes `public/board-model.<id>.json` for each board `game.yaml` lists (`boards:`, in picker order), `public/board-model.json` for the first (the default, which `#/bwrdd` and the rule book open), and `public/boards.json`, the list for the picker. A folder not listed is not built. One file a board keeps each download to the board played; the default copy keeps every current reader working. The compiled `game` holds the calendar and the board in play (`board`, `region`, `councils`, `areas`, `map_groups`), so the engine still reads `model.game.councils` and nothing in the rules knows which board it is.
- **Saves and run codes name the board.** The compiled `save_key` is game.yaml's prefix plus the board id ("etifeddiaeth.board.v2.southeast."). Keys saved before boards move under the first board opened, key by key, and are removed singly (`src/board/ui/saves.ts`); an old run code is dropped, as it names no board. `BoardState.board` holds the id, and run codes are now `b3.` with the board id after the version (`runBoard` reads it), so a code is refused on another board with a plain message.

**Consequences.** Adding a board is a folder and one line in `game.yaml`. The South East compiles to the same model as before apart from the new board fields, its save key and `area` for `flag` (checked by a structural diff against the model before the change, and the quick bot table is unchanged). Old `b2.` run codes no longer open. Shared files that still name the valleys branch's projects (`pairs.yaml`, `events.yaml`) must move those lines to the South East's folder or name shared projects before a board without that branch builds (`src/board/NEEDS.md`, package 14).

**Shared lines that name one board's projects.** Shared content may name a project that lives in a board's `branch.yaml` (the South East's buses that meet the trains cut the heat and fuel events, and pair with a health hub). On a board without that project the build leaves out the line that names it: a pair, an event's size rule or preparation, a place it scales (`scripts/board/other-boards.ts`, the same rule that offers a place only through projects on the board). Only another board's project is left out, so a typo still fails the cross check. A line whose meaning would change without the name, an ending's keystone or a start's free project, is never dropped; it fails the build instead.

## Adding a board

Checked at the v3 A1 join by adding and removing a throwaway board (five Gwent councils, its own branch with two of its five projects renamed): it built strict, the pair naming a South East project was left out as a second model, appeared in `public/boards.json`, and every balance bot finished games on it. Create these files and nothing else:

1. `model/board/boards/<id>/board.yaml`: `name` (`{ en, cy, cy_review: true }`), `councils` (codes from `model/authorities.yaml`, in display order), `areas` with `core` and `edge` as lists of council flags, `map_groups` (`[]`, or groups with `id`, `name` and `councils`), `stubs` (off-board places at the map edge, `id: "stub:<name>"`, `name`, `centre` in the km frame), optional `stops`.
2. `model/board/boards/<id>/branch.yaml`: the board's first branch (`branch:` with its tiers) and its `projects:`, in the shape every board shares: two starters, a quick project, a bigger one, a keystone and a legacy project.
3. `model/board/boards/<id>/starts.yaml`: the starts on offer (or none, if a shared `model/board/starts.yaml` serves it).
4. Optional: `events.yaml` (new events, or a shared one replaced by id), `words.yaml` (renamed text fields by section and id).
5. Add `<id>` to `boards:` in `model/board/game.yaml` (first in the list is the default board at `#/bwrdd`).
6. Run `npm run board:build -- --strict`. It writes `public/board-model.<id>.json` and the picker list; a board removed from `boards:` has its file removed.

A place on the board needs no step: places live in `model/board/places/`, and a board takes every place on its councils.

**Not yet true (src/board/NEEDS.md, the A1 join).** A board whose branch has no `work-up-the-line` keystone fails on the ending The joined-up valleys, which names it; and four outside events (`hot-summer`, `work-changes`, `rents-rise`, `fuel-jump`) keep fewer than the two tier 1 preparers fairness rule 3 needs once `buses-meet-trains` is left out. Until those close, a board builds only if its branch keeps those two projects (the throwaway did); with all five renamed it failed on exactly these lines.
